# プルリクエストの作成

ブランチの状態と差分を確かめてから、日本語の PR を作る。本文は、レビューする人が差分を開く前に「何が・なぜ変わったか」と「どう確かめるか」を分かるように書く。

## 手順

### 1. ブランチの状態を確かめる

```bash
git fetch origin
git status -sb
git log --oneline origin/<ブランチ名>..HEAD
```

- 未コミットの変更があれば、PR に含めるかどうかをユーザーに聞く。勝手にコミットしない
- push されていない、またはリモートとずれている場合は、push してよいかをユーザーに聞く

### 2. ベースブランチを決める

原則は `develop`。ユーザーが別のブランチを指示したときだけ、それに変える。

理由：このリポジトリの機能ブランチは `develop` にマージしている（PR #1）。`main` と比べると、`develop` にマージ済みのコミットまで差分に入ってしまう。

### 3. 既存の PR がないか確かめる

```bash
gh pr list --head <ブランチ名> --state all
```

開いている PR があれば、新しく作らず、その URL をユーザーに伝える。本文を更新したいかどうかを聞く。

### 4. 差分を読む

ローカルの `main` や `develop` は古いことがあるので、必ず `origin/` 付きのブランチと比べる。

```bash
git log --oneline origin/<ベース>..HEAD
git diff --stat origin/<ベース>...HEAD
git diff origin/<ベース>...HEAD -- <主要なファイル>
```

`pnpm-lock.yaml` などの自動生成ファイルは、中身まで読まなくてよい。

### 5. タイトルと本文を書く

タイトルは日本語で、変更の目的が分かる1行にする。本文は次の構成にする。

```markdown
## 概要

<何をしたかと、その目的を2〜3文で>

## 変更内容

### <領域ごとの見出し（例：フロントエンド（`apps/web`））>
- <変更点。理由が差分から読み取れないものは理由も書く>

## 動作確認

1. <再現できる手順>
```

本文の末尾には、システムから指示された attribution の行を付ける。

本文は scratchpad ディレクトリにファイルとして保存する。`--body` に直接書くと、改行や記号のエスケープで崩れやすいため。

### 6. ユーザーの確認をとる

ベースブランチ・タイトル・本文をユーザーに見せ、了承を得てから作成する。

### 7. PR を作成する

```bash
gh pr create --base <ベース> --head <ブランチ名> --title "<タイトル>" --body-file <本文ファイルの絶対パス>
```

作成できたら、PR の URL をユーザーに伝える。

## 守ること

- **`gh` は単独のコマンドで実行する。** `cd` や `&&`、パイプと組み合わせない。`gh *` はサンドボックスの `excludedCommands` に入っているが、コマンド全体が一致しないとサンドボックスの中で実行され、TLS エラー（`x509: OSStatus -26276`）で失敗する
- **ベースブランチを推測で変えない。** `develop` 以外にするのは、ユーザーが指示したときだけ
- **ユーザーの了承なしに PR を作らない。** push・コミットも同じ
- **差分にない変更を本文に書かない。** 動作確認の手順も、実際に確かめられる内容にする

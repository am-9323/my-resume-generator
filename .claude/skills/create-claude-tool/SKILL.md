# Skill・サブエージェント・Hook の下書きを作る

このプロジェクトでは、ツールの下書きを Claude が書き、ユーザーが確認する。ユーザーは Claude Code の仕組みを学んでいる最中なので、下書きと一緒に「なぜそう書いたか」を説明する。

## 手順

### 1. 既にあるものを確認する

```bash
ls .claude/skills/ .claude/agents/ 2>/dev/null
```

あわせて `.claude/settings.json` の `hooks` も確認する。似た役割のものがあれば、新しく作らず、既存のものの改善を提案して止まる。

### 2. 目的ときっかけを整理する

会話から、次のことを拾う。足りなければユーザーに聞く。

- 何をさせたいか
- どんな場面で使うか（ユーザーが実際に言いそうな言葉）
- 作ろうと思ったきっかけになった出来事（同じ指示の繰り返し、つまずき など）

きっかけの出来事は、下書きの中の手順や「守ること」に反映する。同じつまずきを防ぐのが、ツールを作る一番の理由になる。

### 3. 種類を決める

| 種類 | 向いているもの | 置き場所 |
|---|---|---|
| Skill | 決まった手順や知識。今の会話の文脈を使って作業する | `.claude/skills/<名前>/SKILL.md` |
| サブエージェント | 独立した作業（レビュー、調査）。結果だけを返し、メインの会話を散らかさない | `.claude/agents/<名前>.md` |
| Hook | 「毎回必ず」実行したい決まった処理。Claude の判断に任せない | `.claude/settings.json` の `hooks` |

ユーザーが種類を指定していても、別の種類の方が合うと考えたら、理由を添えて提案する。

### 4. 下書きを書く

**共通**

- 本文は日本語で書く。指示は具体的にし、「なぜそうするか」を短く添える
- `CLAUDE.md` に書いてあるルールは繰り返さない。必要なら「`CLAUDE.md` に従う」と書く
- 最後に「守ること」の節を置き、やってはいけないことをはっきり書く

**Skill**

- frontmatter は `name` と `description`
- `description` で、自動で呼ばれるかどうかが決まる。「何をするか」と「どんなときに使うか」の両方を書き、ユーザーが実際に言いそうな言葉を入れる
- `/名前` で明示したときだけ使いたいものは、`disable-model-invocation: true` を付けるかどうかをユーザーに確認する

**サブエージェント**

- frontmatter は `name`・`description`・`tools`
- `tools` は必要なものだけに絞る。ファイルを書き換えないエージェントには `Edit` と `Write` を渡さない
- サブエージェントは今の会話を見られない。呼び出すときに何を渡すべきかを `description` に書く
- 結果の報告の形式を決めておく

**Hook**

- `.claude/settings.json` は保護されているので、直接書き換えず、追加する JSON を示して確認をとる。設定の書き方は `update-config` Skill に従う
- コマンドが失敗したときに作業全体を止めてしまわないかを確かめる

### 5. ユーザーに説明する

次の順で伝える。

1. 作ったファイルの場所
2. 構成と、そうした理由（きっかけの出来事とどう結びつくか）
3. 判断が分かれた点と、選ばなかった案
4. 試し方。きっかけの出来事を再現できる題材があれば、それを使う。新しいサブエージェントは、Claude Code の再起動か `/agents` で認識される
5. 確認してほしい点

## 守ること

- **ユーザーの了承なしに作らない。** 提案の段階では、ファイルを作らない
- **コミットしない。** ユーザーが確認してからコミットする
- **Claude のメモリには書かない。**
- **一度に1つだけ作る。** 複数作りたいときも、1つずつ確認をとる

# 要件定義書（MVP）

## 1. 概要

履歴書・職務経歴書の記載内容をWeb上で管理し、PDFとして出力するアプリ。
経歴は今後も増えていくため、1件ずつ追記しやすい構造で保持する。

## 2. 前提・方針

| 項目 | 決定事項 |
|---|---|
| 利用者 | 自分専用（ログインあり。新規登録は無効化） |
| 運用 | 無料枠でWeb公開（例: Vercel + Supabase）。スマホからも追記できる |
| 履歴書の様式 | 厚生労働省の履歴書様式例（2021年） |
| 職務経歴書の形式 | 逆編年体（新しい経歴から記載） |
| 日付表記 | データは西暦で保持し、PDF出力時に和暦か西暦かを選ぶ |

## 3. 機能要件

### 3.1 認証
- メールアドレス（または Google）でログインできる
- 自分以外のアカウントは作成できない
- データはログインユーザーごとに分離する

### 3.2 基本情報（1ユーザーにつき1件）
- 氏名、ふりがな
- 生年月日（満年齢はPDF作成日時点で自動計算）
- 性別（任意。未記載でも出力できる）
- 証明写真（画像をアップロードする。縦40mm×横30mmの比率に合わせる）
- 現住所（郵便番号、住所、ふりがな）、電話番号、メールアドレス
- 連絡先（現住所以外に連絡を希望する場合のみ）

### 3.3 学歴（複数件・追記式）
- 年月、学校名・学部・学科、区分（入学／卒業／中退 など）

### 3.4 職務経歴（会社 > プロジェクト の2階層・追記式）
- **会社**: 会社名、在籍期間（入社年月〜退社年月、在籍中も可）、事業内容、従業員数、雇用形態、退職理由（任意）
- **プロジェクト**: 期間、プロジェクト名・概要、役割、チーム規模、使用技術、担当業務、成果
- 履歴書の「職歴」欄は、会社データの入社・退社から自動で作る（二重入力しない）

### 3.5 免許・資格（複数件・追記式）
- 取得年月、名称

### 3.6 共通の文章
書類ごとに別の文章として持つ。

| 項目 | 履歴書 | 職務経歴書 | 応募先ごとの上書き |
|---|:---:|:---:|:---:|
| 志望の動機、特技、好きな学科、アピールポイントなど | ○ | − | 可 |
| 本人希望記入欄 | ○ | − | 可 |
| 職務要約 | − | ○ | 不可 |
| 活かせる経験・知識・スキル | − | ○ | 不可 |
| 自己PR | − | ○ | 可 |

### 3.7 応募先ごとの出し分け
- 応募先（会社名・メモ）を複数登録できる
- 応募先ごとに、3.6 の表で「上書き可」の項目を書類別に上書きできる
  - 上書きしない項目は共通の文章を使う
- 経歴（学歴・職歴・プロジェクト・資格）は全件を掲載する

### 3.8 PDF出力
- 履歴書と職務経歴書を、それぞれPDFとして出力する
- 出力時に選ぶもの: 応募先（または共通）、日付表記（和暦／西暦）、作成日
- 日本語フォントを埋め込み、どの環境でも文字化けしないようにする
- 履歴書はA4（またはA3の見開き相当）で、厚労省様式例のレイアウトに準じる

## 4. 非機能要件
- 個人情報を扱うため、他人のデータを読み書きできないようにする（方式は `docs/tech-stack.md` の「認可の方針」を参照）
- 証明写真は非公開のストレージに保存する
- スマホでも入力しやすい画面にする（PDFのプレビューはPCを主に想定）
- 月額0円で運用する

## 5. MVPでやらないこと
- 他ユーザーへの公開・ユーザー登録機能
- 応募先ごとの掲載プロジェクトの選択（将来の拡張候補）
- スキルシート、Markdownでの文章入力（将来の拡張候補）
- 旧JIS様式、編年体・キャリア式の職務経歴書
- Word・Excel形式での出力

## 6. 未決事項
- なし（技術面の未決事項は `docs/tech-stack.md` で管理する）
